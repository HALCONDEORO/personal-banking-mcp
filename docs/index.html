The connected surface

Five read-only tools.

All five operate on embedded fixtures. They do not call a bank, write financial state or activate the isolated provider experiments.

ToolPurpose
list_accountsList two fictional accounts, without balances.
get_balanceRead an invented decimal balance and currency.
get_transactionsPage through bounded date ranges of synthetic movements.
search_transactionsFind literal description matches within selected fixtures.
summarize_transactionsSeparate inflow, outflow and net by currency and status.

Transaction dates are inclusive, with at most 366 days per range. A completed page is not evidence of a complete real bank history. See the README for arguments and limits.

Quick start

Your machine.
Invented accounts.

Python 3.10 or newer and pip. Clone the repository, create a virtual environment and run the demo from the project root.

On Windows, use py -3 -m venv .venv and run .venv\Scripts\python.exe directly if activation is restricted. No execution-policy changes are required.

Full install and client configuration ↗
git clone https://github.com/HALCONDEORO/personal-banking-mcp.git
cd personal-banking-mcp
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check
python -m unittest -q
python test_server.py --demo

Local execution does not make your AI client offline. It may send returned data to an AI service. Check its privacy settings.

What stays outside

Not a banking app.
Not a promise.

  • No live bank or Revolut connection.
  • No payment, trading or account-changing tool.
  • No public API, hosted financial dashboard or telemetry.
  • No claim of production readiness or regulatory approval.

Separate experiments

Provider work and pure analytics

Normalization, pagination, consent design and request budgets are tested with synthetic transports. Export and recurring-charge candidates are pure library functions, not extra connected MCP tools.

A recurring pattern is not a confirmed subscription or predicted debit. Never put real statements, credentials, keys or session tokens into the repository, issues, logs or screenshots.

Read the implementation boundaries ↗

The finished-product goal

A real read-only connection.
Under the owner's control.

The destination is a personal banking MCP that reads authorized accounts through Enable Banking, keeps the signing key on the owner's computer and makes accounts, balances and transactions useful without moving money.

TARGET / CONNECT

Supported bank consent

Reviewed registration, an accepted redirect and account-owner SCA. Published Revolut coverage is not proof that a particular account works.

TARGET / PROTECT

Local signing and recovery

Verified Windows key custody, permissions, safe transport, private storage, revocation and cleanup. These are release gates, not completed features.

TARGET / UNDERSTAND

Useful bounded analysis

Exact read-only data, clear provenance and explainable search, summaries and patterns. No fabricated completeness, subscriptions or fraud claims.

Current status: synthetic MCP only. No live bank has been connected through this project workflow. No delivery date, production-readiness claim or account-specific compatibility promise.
